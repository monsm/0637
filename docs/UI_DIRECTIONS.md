# 手机 App UI/UX 设计 · 三套方向（2026-11-09）

> 当前界面是"调试面板"：左上状态卡、左下摇杆、右侧一列按钮。它能用，但它展示的是
> 一个**仿真器**，不是一只**鸭子**。下面是三个方向，分别回答"这只鸭子是什么"。

---

## 方向 A · 「活的」 Live Duck

**定位**：这是一只宠物，不是一台设备。界面退后，鸭子在前。

**核心主张**：屏幕上 80% 是鸭子和它的房间，控件只在需要时出现。所有传感器和遥测都
收进一个可以拉出的抽屉，默认不打扰。

**关键交互**

| 流程 | 设计 |
|---|---|
| 遥控 | 全屏触摸板：手指按在鸭子**前方**的地面 = 走过去；按在它左右 = 转身。松手即停。没有可见摇杆。 |
| 技能 | 长按鸭子 → 环形菜单（转一圈 = 翻滚，向左/右拖 = 踢腿，向下拖 = 坐下，向上 = 抓取）。 |
| 状态 | 不给数字，给**姿态**：鸭子低头 = 累了，耳朵/头歪 = 好奇。摔倒时画面轻微震动 + 一声 quack。 |
| 传感器 | 抽屉里"它感觉到了什么"：麦克风电平化成羽毛抖动，相机亮度化成房间色温，IMU 化成一阵风。 |
| 时间机器 | 双指下滑 → 时间轴从底部升起（像相机胶卷）：拖动倒带，松手回放；左侧"冻结"按钮；右侧分叉按钮把当前帧撕成两半。 |

**信息架构**

```
鸭子（全屏）
├─ 触摸即控（无 UI）
├─ 长按 → 环形技能盘
├─ 双指下滑 → 时间轴
│   ├─ 倒带 / 冻结 / 单步
│   ├─ 分叉（拖出一个副本）
│   └─ 事件标记：技能、推挤、摔倒
└─ 上滑 → 抽屉
    ├─ 传感器（相机/麦克风/深度/IMU）
    ├─ 这只鸭子（指纹、策略、保真度）
    └─ 连接（AI API :8765 / MCP）
```

**视觉风格**：暖白背景、柔和阴影、圆角、无边框；鸭子有真实的接触阴影和呼吸起伏。
字体用圆润的无衬线（SF Rounded / Google Sans），几乎没有数字。

**优点**：最像"产品"，最像真鸭子；传感器和时间机器都不打扰主体。
**风险**：隐藏控件对新手不友好；无数字的状态需要精心设计才不"糊"。

---

## 方向 B · 「仪器」 Instrument

**定位**：这是一台可观察、可复现、可实验的机器。给工程师和 AI 研究者用。

**核心主张**：一屏之内同时看到**物理状态、策略决策、时间轴**。所有数字都在，但排布
得像示波器而不是表单。

**关键交互**

| 流程 | 设计 |
|---|---|
| 遥控 | 左下摇杆（保留），右侧是**推力/方向矢量**的实时读数；摇杆旁显示 deadman 倒计时环。 |
| 技能 | 底部一排"通道条"（像调音台）：每个技能一条，显示剩余时间、优先级、是否被抢占。点击触发。 |
| 状态 | 顶部三联：`label` / `bringup` / `gain`；中部叠加层（X 光）：接触点、CoM、支撑多边形、摔倒预测余量。 |
| 传感器 | 右侧纵向"仪表条"：相机帧缩略、麦克风波形、深度网格 8×8、IMU 三轴。每项标 `mode` 和 `in_observation`。 |
| 时间机器 | 底部固定时间轴（始终可见）：tick 刻度、检查点刻度、事件标记；拖拽 scrub，空格冻结，`[` `]` 单步。 |

**信息架构**

```
┌ 顶部：label · bringup · gain · tick ─────────────┐
│                                                  │
│              3D 视图 + X 光叠加层                │  ← 右：传感器仪表条
│                                                  │
├ 底部：摇杆 ─ 通道条（技能）─────────────────────┤
└ 时间轴：刻度 / 检查点 / 事件 / 播放头 ──────────┘
```

**视觉风格**：深色、等宽字体、细线、发光的强调色（青/琥珀）；数字右对齐；网格对齐。
像飞行仪表或专业音频软件。

**优点**：信息密度最高；时间机器和传感器"天生"属于这个布局；适合演示"这是真的"。
**风险**：不像宠物；小屏手机上密度过高。

---

## 方向 C · 「导演」 Director

**定位**：这是一台**摄影机**。你拍它，不是开它。

**核心主张**：主界面是取景器。鸭子在一个真实的房间里（AR 或虚拟场景），你能换机位、
调光、录片段、做回放蒙太奇。控制是次要的，收在一个"驾驶"模式里。

**关键交互**

| 流程 | 设计 |
|---|---|
| 遥控 | 进入"驾驶"模式后出现方向盘式控制（左右两个拇指区：左 = 移动，右 = 转头），像主机游戏。 |
| 技能 | 技能 = "动作"卡片，在时间轴上以**片段**形式出现，可以拖长、缩短、叠加。 |
| 状态 | 取景器角落的小 HUD：电量式条显示"健康"（摔倒风险）、"心情"（空闲/活跃）。 |
| 传感器 | 相机就是取景器本身；深度用于地面吸附（AR）；麦克风用于"声音触发录制"。 |
| 时间机器 | 录制 = 一直录。底部是**剪辑条**：选片段 → 慢放 → 分叉成两条时间线并排对比 → 导出视频。 |

**信息架构**

```
取景器（AR 或虚拟房间）
├─ 机位（拖动环视，双指缩放）
├─ 录制 / 剪辑条（底部）
│   ├─ 片段缩略
│   ├─ 慢放 / 倒放
│   └─ 分叉对比（A/B 双画面）
└─ 驾驶模式（切换）
    ├─ 双拇指控制
    └─ 动作卡片
```

**视觉风格**：电影感——宽画幅、浅景深（模拟）、胶片颗粒可关、字体极简（Helvetica Neue
细体），控件半透明浮在画面上。

**优点**：最"出片"，最能展示 AR 和 PBR 的价值；时间机器变成剪辑语言，很自然。
**风险**：偏离"1:1 复刻"的工程叙事；录制/导出需要大量新功能。

---

## 推荐

**选 A（「活的」），并把 B 的时间轴和传感器仪表作为可拉出的第二层。**

理由：

1. **目标是"app 里的就是真鸭子"**。真鸭子不会在你面前摆一排按钮和 tick 计数——A 是唯一
   从"它是一只鸭子"出发的方向。
2. A 不牺牲能力：时间机器（双指下滑）、传感器（上滑抽屉）、MCP/AI 连接都在，只是分层。
3. B 的优点可以嫁接：时间轴在 A 里是全屏手势唤起的，可以做成 B 的密度。
4. C 的价值（AR/录制）是后续的**模式**，不是主界面；A 的取景器结构能容纳它。
5. 工程风险最低：现有 3D 视图和 intent API 不变，只重写外壳。

**落地顺序**：全屏鸭子 + 长按环形菜单 → 双指下滑时间轴 → 上滑抽屉（传感器/指纹/连接）
→ AR 模式作为抽屉里的一个开关。
