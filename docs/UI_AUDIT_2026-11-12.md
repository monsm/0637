# UI/UX 审计报告 · MicroDuck 数字版（2026-11-12）

> 审计人：阿雅（UI/UX）· 审计小组（六路并行：iOS 界面 / Android 界面 / 视觉系统 / 文案本地化 / 无障碍人体工学 / 信息架构）
> 代码基线：`ccdedb4`～`be5db91`（`D:/AI/Duck`）· 详细分册见文末「附录」。

## 一、一页读懂

**这版界面是给引擎看的一屏，不是给鸭子看的一屏。**

功能做了很多（七个陪伴功能 + 画路走 + 睡眠 + 合唱 + 互送 + 日记 + 规则分享），CI 也一直绿。但把六份审计并排看，结论是同一件事：

| 面 | 现状 | 方向 A 要求的 |
|---|---|---|
| **首屏** | 顶栏 + 状态胶囊 + 时间栏 + 拇指台，chrome 占竖屏 **23%（iOS）～ 40%（Android）**，鸭子只剩 14%～55% | 屏幕 80% 是鸭子 |
| **文字** | 顶栏直出 core 协议串 `idle` / `held` / `mode: walk`、原始技能名 `kick_left` / `roulade`、`t 302`、`content · mood 67%`、`Loading MuJoCo + policies…` | 状态"不给数字，给姿态" |
| **视觉** | token 底子 = 0：主色 **9 个值**、字号 **12 档**、圆角 **8 档**、深色表面 **7 个值**、强调色无分工 | 一套 token，一语义一值 |
| **舞台** | 官方 MuJoCo 蓝灰棋盘（0.2 m 一格）+ 冷黑虚空 | 鸭子站在一个房间里 |
| **反馈** | 摔倒 = 一行 11pt 橙字；冻结 = 图标硬切；chip 按下无反馈；全应用触感 1 处 | 鸭子是活的，事件有戏 |
| **无障碍** | iOS 动态字体 171 处全失效；状态变化两端零播报；手势是唯一入口且无替代 | 看得见、听得出、够得到 |
| **可发现性** | Android 的画路走/邻居只在 ⋯ 菜单纯文字行；仪表里 12 个功能挤一屏 | 功能做完了要能被找到 |

**一句话结论**：功能层已经跑在前面，界面层还停在调试面板。下一步不是加功能，是**把已有的东西从"能用"做成"像个产品"**——而且这件事现在做，比三个月后做便宜一个数量级（现在建 token 是"归位散落的字面量"，三个月后就是"重构稳定的系统"）。

## 二、P0（不做就不像个产品）

### P0-1 · 首屏把引擎的状态机当正文显示（两端）

- **现象**：iOS 顶栏第二行是 `controller.label`——core 里 `char label[64]` 的原样拷贝：待机 `idle`、被拎 `held`、摔倒 `limp_fall`、切模式 `mode: walk`、加载完 `policy reloaded`。Android 顶栏另直出协议技能名 `kick_left` / `roulade` / `yes_fast`。
- **证据**：`ios/DuckApp/ContentView.swift:1084`（`Text(controller.ready ? controller.label : Copy.waking)`，值来自 `DuckController.swift:2176-2179` 原样 `String(cString:)`）；`android/.../Shell.kt:1561-1569`；core 侧 `core/duck-mobile-core/src/runtime.rs:2268/2311/2328/2406/2525`、`ffi.rs:356/640`。
- **为什么坏**：这是给工程师看的枚举。VoiceOver 还会把它念出来（`ContentView.swift:1087` 挂了 `duck-label`），盲用户听到的是 "limp_fall"。而且 `SkillLabel.of` 就在同一个文件里（`Copy.swift:421-451`，`kick_left → 左踢`），**翻译函数存在，只是这条路径没走**。
- **改法**：加一层 `Copy.behaviourOf(raw:)` 映射（`held → 被拎着`、`limp/limp_fall → 摔倒了`、`homing → 正在站稳`、`mode: walk → 走路`），未知值兜底"待机"；原始串只留给 Time Machine 面板。技能名一律走 `SkillLabel.of` / `skillLabel`。
- **验收**：两端首屏不再出现任何含 `_` 或全小写英文词的状态/技能名。

### P0-2 · 调试量词直接写在首屏

- **现象**：Android 竖屏有 `t 302`（内核 tick）、`content · mood 67%`（状态字段 + 百分比）；iOS 时间栏有 `t 12345`；心情胶囊平时显示"饱腹 62%"。
- **证据**：`android/.../Shell.kt:1685`（`t 302`）、`Copy.kt:140`（`content · mood 67%`）；`ios/DuckApp/ContentView.swift:588-590`（`Text("t \(controller.simTick)")`，10 pt 等宽，**占了唯一该放"时间"标签的位置**）；`ContentView.swift:1096`；`Copy.swift:172-179`。
- **为什么坏**：违反方向 A 明写的"不给数字，给姿态""几乎没有数字"。`t 302` 会一直变，吸引视线却零信息量，还让那个按钮的用途不可读（用户不知道时钟图标是回放还是暂停）。
- **改法**：tick 只留在 Time Machine 面板（`InstrumentSheet.swift:403` 已有）；心情胶囊只说情绪（"心情不错 / 有点难过 / 睡着了"），百分比改成长按胶囊看详情。
- **验收**：首屏零裸数字。

### P0-3 · 竖屏没有任何错误出口：渲染失败 = 死屏

- **现象**：iOS 竖屏 `portraitChrome` 里**没有**失败分支。核心起不来或 Metal 报错时，用户看到一整块深灰空屏 + 一排 40% 透明度的死按钮，**一个字都没有**。
- **证据**：`ContentView.swift:532-561`（竖屏无 failure 分支）vs `:1044-1053`（横屏有 `failureCard`）；`grep failureMessage` 只命中 1048/1072/1073/1074，全在横屏；失败时连"正在唤醒…"都不显示（`:156` 的条件是 `renderError == nil`）。Android 是另一套：`MainActivity.kt:317-324` 一行裸错误文字。
- **改法**：把 `failureCard` 提到竖屏共用；错误文案换成人话（"Bundle resources not found" → "应用资源不完整，请重新安装"）；失败时不要把控件画成"看起来还能点"。
- **验收**：两端各有一个"启动失败"截图，卡片有中文标题 + 一句原因 + 一个重试。

### P0-4 · 加载屏是工程文案，不是鸭子

- **现象**：Android 首屏正中一句 `Loading MuJoCo + policies…`——整个 App 唯一提到仿真引擎的地方，中文界面也显示英文。旁边还挂着一张调试读数卡（`Ready · gain 200` / `AI API :8765`）。
- **证据**：`android/.../MainActivity.kt:317-324`、`:460-477`；iOS 侧是纯色底 + "正在唤醒…"（`ContentView.swift:156-166`）。
- **改法**：中文文案（"正在唤醒鸭子…"，别提引擎）；加载态给一只正在睡着的鸭子剪影或呼吸动画；调试读数卡删掉（那是仪表表的东西）。
- **验收**：中文用户全程看不到 MuJoCo / ONNX / 端口号。

### P0-5 · 舞台是官方仿真地板，不是房间

- **现象**：Live 的地面是 MuJoCo 官方场景的 groundplane——**0.2 m 一格的蓝灰棋盘**（`mix((0.20,0.30,0.40), (0.10,0.20,0.30))`），背景是死黑 `(0.055,0.075,0.10)`。截图 `dist/current-android.png` 里那半张蓝格网格不是渲染 bug，是照搬。
- **证据**：`ios/DuckApp/Shaders/Shaders.metal:86-92`、`android/.../DuckRenderer.kt:528-532`（棋盘）；`ios/DuckApp/Renderer.swift:296`（清屏色）；`DuckRenderer.kt:165-166`（地面色）。Android 无相机时的合成背景也是冷蓝渐变 `(14,19,26)→(23,28,36)`（`PhotoCapture.kt:38-46`）。
- **为什么坏**：方向 A 的第一句就是"这是一只宠物，不是一台设备"。用户第一眼看到的是**仿真器地板**。更要命的是：**明信片/照片就是这一帧原样存下来的**（`PostcardShelf.keep(image:)` 存渲染帧 PNG，`Share` 交出去的也是这张）——用户要发朋友圈的图里带着 20 cm 一格的调试网格。
- **改法**：见 `docs/STAGE_LOOK.md`。Live 地面换暖石哑光、背景换竖向渐变 + 鸭身后暖光晕；棋盘格只留给 Instrument（仪表盘用冷色网格是正统语言）；Director 模式加一块半透明接触阴影盘，相机不可用时不要让鸭子悬空。
- **验收**：新的竖屏 Live 截图，地面没有格子；一张明信片分享件，右下角有日期。

### P0-6 · 明信片分享出去的是一张没字的裸图

- **现象**：caption（被摸 / 喂食 / 仪式 / 摔倒 / 情绪 / 米数，全是真实计数）**已经算出来了**，却只活在 App 的元数据里；分享交出去的还是那张裸 PNG。日期同理，只在货架上显示。
- **证据**：`ios/DuckApp/PhotoPreviewSheet.swift:142-153`（caption 生成）、`PostcardShelf.swift:42-67`（存原帧 + 元数据）、`PhotoPreviewSheet.swift:80-88`（分享交原帧）；`android/.../PostcardShelf.kt:43-64, 72-89`、`PostcardsSheet.kt:122-127`。
- **改法**：保存时**合成成片**——图 + 底部 12% 高的深色字幕带（55% 黑）+ 左侧 caption（13 pt rounded）+ 右侧日期（11 pt）+ 右下小字标；原帧另存；分享交成片。caption 一字不改，它必须还是真数字。
- **验收**：分享出去的 PNG 自己就带日期和那一行真实记录。

### P0-7 · iOS 动态字体完全失效（171 处固定字号）

- **现象**：全仓 171 处 `.font(.system(size: N))`（分布在 10 个文件），语义字体 `.font(.body/.caption/...)` **0 处**，`UIFontMetrics` / `relativeTo:` / `@ScaledMetric` **0 处**。SwiftUI 的 `.system(size:)` 是固定磅值，不随系统字号缩放。Android 用 `sp` 会缩放 —— **同一份设计，两端对"放大字体"的响应完全不同**。
- **证据**：`ContentView.swift:161`、`:506`、`:567`、`:588`、`:1092`；`InstrumentSheet.swift:163/431/473`；`DanceSheet.swift:57/61` 等。
- **为什么坏**：低视力的老人、举远看的孩子——在 iOS 上把字号调到最大，界面一点都不会变。
- **改法**：逐条映射到 8 档语义字体（`.largeTitle/.title2/.title3/.headline/.body/.subheadline/.footnote/.caption`）+ `design: .rounded`，超大档用 `.dynamicTypeSize(...accessibility3)` 封顶避免撑破布局。Android 同批把固定 `dp` 容器改成 `heightIn(min:)`（`Shell.kt:2445/2371/1669/1749`）。
- **验收**：iOS 字号放到最大，Live 首屏与仪表 sheet 都不裁字、不重叠。

### P0-8 · 舞台手势没有任何无障碍替代

- **现象**：走 / 转身 / 摸 / 画路**全部**挂在裸手势上。两端 `accessibilityAction` / `customActions` 命中数都是 **0**。TalkBack 用户永远走不了第一步。
- **证据**：`ContentView.swift:117-129`（`portraitDriveGesture` + `onLongPressGesture(0.35)`）、`:816-908`；`android/.../Shell.kt:1812-1968`、`:1976-1991`（`:1867` 明写"ring 开着就不许驱动"，等于承认手势是唯一入口）。
- **改法**：`scene` 加 4 个自定义动作——「向前走一步」「左转」「右转」「摸摸它」「打开技能圈」（iOS `accessibilityCustomActions`，Android `Modifier.semantics { customActions }`），脉冲值复用 `ContentView.swift:890-900` 已有的 250 ms 逻辑；`scene` 给 `accessibilityLabel("鸭子舞台")`。
- **验收**：TalkBack 能让鸭子走一步、转个身、摸一下。

### P0-9 · Android 编舞正在播放的那格是白字压黄底（1.36:1）

- **现象**：编舞播放中当前步底色 `#FFD54F`（黄），文字仍是白字 90%。WCAG 手算 **1.36:1**（正文要 4.5:1），序号那行 1.20:1。**iOS 同一功能是对的（黑字压黄底）** —— 这是 Android 单端回归。
- **证据**：`android/.../DanceSheet.kt:142-143`、`:155-161`；对照 `ios/DuckApp/DanceSheet.swift:64`。
- **改法**：抄 iOS——选中格文字改 `Color.Black`；再给序号加粗或描边，别只靠色相。
- **验收**：编舞播放中那一格一眼可读。

### P0-10 · chrome 比鸭子抢眼（首屏 23%～40% 是控件）

- **现象**：iOS 竖屏 chrome 约 23%（顶栏 + 时间栏 + 拇指台），Android 竖屏约 40%（状态卡 12% + 胶囊 + 时间栏 + 拇指台 28%），**鸭子只剩 14%（iOS 缩略）～ 55%（Android 舞台）**。方向 A 要求鸭子 80%。
- **证据**：`dist/current-android.png`（320×640 实测：状态卡 y≈0-77、舞台 y≈112-459、时间栏 y≈512-554、拇指台 y≈571-629）；`ContentView.swift:532-561`（竖屏 chrome 结构）。
- **改法**：Live 首屏只留**四个动词**（喂 / 技能 / 叫 / 摸）+ 一个"更多"抽屉；时间栏、积木、邻居、编舞、日记、挑战等全部下沉到抽屉里分层；iOS 拇指台 6 个圆钮统一成 52 pt + 18 pt 字形 + 下方 11 pt 文字标签（现在 44/46/50/56 四个直径混用、无一有字）。
- **验收**：新截图里，鸭子连同地面 ≥ 70% 画面。

## 七、需要拍板的三件事

1. **中文圆体字**：SF Rounded 和 Roboto 都没有中文字形，"圆润"这个人格在中文界面里自动消失。要不要随包放一份中文圆体（思源黑体圆体 / HarmonyOS Sans SC）？**许可 + 包体 + 两端字形匹配**是三件事，要拍就现在拍，不拍就写进文档承认"中文界面用直角"。

3. **Android 补不补齐 iOS 的功能**：传感器 / 出处 / 重载 AI / 倾斜看，iOS 有 Android 没有。补齐要工，不补就要在 `COMPANION.md` 里写明"Android 不做"，别让文档继续骗人。
