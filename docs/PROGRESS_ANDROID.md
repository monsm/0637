# Android 成长手册 / 成就墙 · 立项与验收标准（小满，2026-11-16）

> 老板 2026-11-16 拍板：Android 补成长手册/成就墙，单独立项。产品归小满，
> 施工小鹿，验收小盯。红线：**数据必须走真实事件账，与 iOS ProgressStore
> 同源语义；盲改环境里不许编造任何历史数据；历史空的就是空的，诚实标注。**

## 1. 这是什么

Android 的「记录」组 →「每日任务」页新增成长手册区块：连续天数、最近 7 天
日历条、10 枚成就（与 iOS `ProgressKit.swift` 的 `Achievement.catalog` 同
id、同判定条件）。它是**同一套本地事件账**的第二个读者，不是另一套数据。

## 2. 事件账（与 iOS 同源语义，逐条对齐）

| 事件 | iOS 挂点 | Android 挂点（本批） | 语义 |
|---|---|---|---|
| `pet` | `pet()` 意图调用处 | 所有 `POST /pet` 的用户动作（大按钮/场景点击） | 一次真实抚摸 |
| `feed` | `feed()` 意图调用处 | 所有喂食入口（拇指台/大字模式/编舞步） | 一次真实喂食 |
| `trick` | `life.skills.roulade` 首读后的增量，每次最多 10 | 同一个源、同一增量规则 | 鸭子真的翻滚了 |
| `walk` | `life.metres` 增量：有增量累计，停走一条 poll 后结一次 | 同一算法 | 鸭子真的走了米数 |
| `photo` | 快门成功 | Director 快门合成成功 | 一张真实照片 |
| `peer` | `gift_event.ok == true` | 同一个字段、同一个判定 | 邻居礼物**真的**生效了 |

**不许**从点击处记 `peer`（iOS FE-2 的教训：点击不等于鸭子收到）；**不许**
从 `peer_event`/握手记；**不许**在首次读 `/state` 时回填历史——首次读只建
基线（iOS 的 `walkBaselineMetres`/`lastRecordedRolls` 同款），历史空就是空。
礼物同理：`gift_event` 会持续发布最后一份礼物，启动后的第一次发布只点
提示不记账；tick 变化后的新礼物才入账。

## 3. 存档（与 iOS schema 对齐）

- 单文件 JSON：`schemaVersion=1`、`days`（近 30 天活跃日累计，key=`yyyy-MM-dd`）、
  `totals`、`bestWalk`、`bestStreak`、`unlocked`（id → 解锁日，只增不删）。
- schema 不符/文件损坏：从零开始，旧文件下次保存时覆盖；绝不猜测恢复。
- 原子写盘：先写临时文件再 rename；失败只丢本次增量，内存事实仍在。
- 跨天：本地自然日；刷新面板/跨天通知时重算快照（只读不落盘）。

## 4. 成就（10 枚，同 id 同条件）

`first_trick` / `first_feed` / `first_postcard` / `first_gift` / `streak_3` /
`streak_7` / `walk_100` / `pet_100` / `late_night` / `walk_30_single`。
解锁后永不回退；解锁日写当天 key。

## 5. 验收标准（小盯）

1. **同源语义**：六个事件挂点与上表一一对应；`peer` 只认 `gift_event.ok`；
   首次读不回填。代码审查 + 单测各一条。
2. **诚实空态**：全新安装、从未发生事件时，面板显示「还没有记录」一句，
   不显示 0 天连击的假庆祝、不显示任何编造的日期/数字；成就全部灰。
3. **JVM 单测**（无模拟器可跑）：连续天数（含今天未活跃不断连）、30 天裁剪、
   成就判定与解锁日、schema 损坏归零、散步会话结算（增量→停走→结算）、
   翻滚增量上限 10、`peer` 仅 ok、空账快照。
4. **两端一致**：同一 id 的成就名称/条件与 iOS 一致（Copy 键两端同推，
   键集相等门禁绿）。
5. **CI**：Contracts / Android 全绿；smoke 打开「每日任务」页断言成长区块
   存在且空态诚实；不新增棘轮债务（固定字号/手抄关闭钮/按压零反馈）。
6. **不做**：不迁移/伪造 iOS 历史；不同步云端；不改核心；不动 61 维。

## 6. 风险与对策

- **事件挂点漏接**：挂点集中在 Shell 的 `/state` 1 Hz 循环与三个意图入口；
  单测覆盖 store，挂点由代码审查 + smoke 的「喂一次后今日计数 +1」断言兜底。
- **重复记账**：所有事件走单一 `ProgressStore.record`，`peer`/`photo` 用
  tick 去重（与 iOS 的 gift tick 同法）。
- **盲改环境**：本机无 Android SDK，编译与 UI 只信 CI；Kotlin 侧先交
  JVM 单测（可与 CI 同跑），再交 smoke。
