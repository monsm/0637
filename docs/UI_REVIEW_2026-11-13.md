## 二、偏离规格的（B2/B3 收掉）

### 1. 时间栏换成了"墙钟时间"，不是时间机器

`ContentView.swift:604-610`：

```swift
// 真实时间，不是 tick。这个按钮通向时间机器，标签就该像一只钟
Text(Date.now, style: .time)
    .font(.system(.caption2, design: .monospaced))
```

tick 拿掉了是对的，但**墙钟时间有两个问题**：

- 系统状态栏右上角已经有一个时间，屏幕上出现第二个钟；
- 它每分钟都在变，仍然是一个"会动的数字"——只是换了个数字；而它打开的是时间机器，用户会以为那是"当前时间"。

**建议**：改成 `Copy.time`（"时间"）或时间机器图标 + 保留历史的进度条（进度条才是这个按钮真正的信息）；墙钟留给仪表盘。

### 2. 进度条仍是系统蓝、仍是 60% 透明

`ContentView.swift:618` `Color.accentColor.opacity(0.6)` —— 审计 P1-10 的 **2.11:1** 对比度问题原样保留。用 `accent.data` 实色（`#7FB2D9`）。

### 3. Instrument 还是暖石地面：两种视觉语言没分开

`Renderer.swift:459-461` 自己留了 TODO：

```
// 冷棋盘路径在 shader 里保留（look 2），但 iOS 的 Instrument 是一张
// SwiftUI sheet，渲染器看不见它的开关；等控制器有了 surface 标志，
// 把这里的 look 换成 2 即可（TODO）。
```

现在 **Live 与 Instrument 长得一样**，`STAGE_LOOK §3` 的"暖 ↔ 冷"分工没落地。要么给控制器加一个 surface 标志（小改），要么在文档里明确"v1 不做"——二选一，别悬着。

### 4. 日光按本地时间染色（规格外新增）

`Renderer.swift:319-348`：凌晨/夜里曝光 **0.72**、清晨暖金、傍晚橙红。方向是对的（房间跟一天一起变，鸭子更像活的），但三个风险要在文档里定死：

- **夜间可读性**：0.72 曝光叠在本来就暗的场景上，凌晨三点的鸭子会不会看不清？给个下限（建议不低于 0.80）。
- **明信片会跟着变暗**：成片是拿渲染帧合成的，夜里拍的明信片偏暗，分享出去像欠曝。
- **CI 判帧会假红**：`scripts/check-frame.py` 用两帧比对判断"渲染器有没有起来"，白天和夜里跑结果不一样。**daylight 必须做成可注入参数**（测试传固定值）。

设计决定：**保留日光，补曝光下限，并把时间做成可注入**。这三条写进 `STAGE_LOOK §2.4`。
